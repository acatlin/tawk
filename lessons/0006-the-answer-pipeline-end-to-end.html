Why this matters for your bot

Visitors never experience a retriever or a matcher. They experience a policy: how quickly they got a right answer, whether the bot admitted ignorance, and how painless the handoff was. This lesson assembles the pieces into that policy and makes every decision observable, so next month you tune numbers instead of arguing about anecdotes.

The pipeline

Each boundary has a one-sentence justification:

  • Tier 0 before everything: a visitor who asks for a person should not have to argue with a bot; the check is a phrase list and costs nothing.
  • FAQ before the model: deterministic, verbatim, free, auditable (lesson 4).
  • Allow-list filter before the model: defence in depth; the index should already be clean, and this makes a leak a test failure instead of an incident (lesson 5).
  • Grounded or nothing: a model answer without an allowed citation is treated as a fallback, because a confident uncited answer is indistinguishable from a hallucination.
  • Fallback is a handoff offer, not a dead end.

The code is shorter than the diagram

export async function answer(question: string, deps: PipelineDeps): Promise<Answer> {
  const allow = normalizeAllowList(deps.allowedSources);
  const minCitations = deps.minCitations ?? 1;

  if (wantsHuman(question, deps.handoffPhrases))
    return { tier: "fallback", text: "Of course. Connecting you with a person now.", citations: [], confidence: 1, handoff: true, reason: "visitor-requested-human" };

  const faq = matchFaq(deps.faq, question, deps.faqOptions);
  if (faq.hit)
    return { tier: "faq", text: faq.entry.answer, citations: [{ title: "FAQ", url: faq.entry.source }], confidence: faq.score, handoff: false, reason: `faq:${faq.entry.id}` };

  const retrieved = filterToAllowed(await deps.retrieve(question), allow);
  if (retrieved.length === 0)
    return { tier: "fallback", text: fallbackText, citations: [], confidence: 0, handoff: true, reason: "no-approved-chunks" };

  const gen = await deps.generate(question, retrieved);
  const citations = filterToAllowed(gen.citations, allow);
  if (!gen.grounded || citations.length < minCitations)
    return { tier: "fallback", text: fallbackText, citations: [], confidence: 0, handoff: true, reason: gen.grounded ? "insufficient-citations" : "model-declined" };

  return { tier: "sources", text: gen.text, citations, confidence: 1, handoff: false, reason: "grounded" };
}

Every return carries a reason. That string is your analytics schema: count reasons per week and you know whether to add FAQ variants (no-approved-chunks on questions you can answer), fix the crawl (model-declined on questions the pages do answer), or celebrate (grounded climbing).

  const a = await answer(question, {
    faq: FAQ,
    faqOptions: { strategy: "tfidf", threshold: 0.45, margin: 0.1 },   // from your lab run

}

The hybrid worth knowing

Expose answer() behind an OpenAPI 3.0 schema with an x-api-key header. Then, if anyone on your team ever turns on AI Assist, point it at that tool: the same FAQ, the same approved sources, the same guards feed both surfaces. tawk.to’s note that “Each API request is independent” means your endpoint must be stateless per question, which answer() already is.tawk.to Help: custom API integration
